## 0. 한 줄 현황

플레이어 판정(머리치기/내려찍기/스톰프)을 겹침 기반으로 대폭 완화하고, 이동 발판에 캐리 로직을 추가해 통과 버그를 근본 수정했다. 경사에 벽 충돌을 새로 넣었다가 순간이동 버그를 여러 라운드 끝에 잡았다(§2.5, 가장 함정 많았던 부분). 웅크림 스프라이트 스프링 연출·붕괴 예고 재설계·아이템 낙하 물리 등 다수 디테일 버그를 고쳤고, **마지막에 이미지가 아직 없는 상태에서 전 엔티티(아바타·몬스터·블록·아이템) 스프라이트 렌더 시스템을 통째로 만들어놨다** — 시트 파일만 오면 코드 수정 없이 게임에 뜬다.

## 2. 이번 세션에 고친 것 (증상 → 원인 → 수정)

### 2.1 판정 전반 완화 (몬스터 스톰프·블록 머리치기/내려찍기)
- 옆 대미지 판정 폭 0.8배로 좁힘(밟기가 애매한 경우 우선되게), 머리치기/내려찍기 겹침 허용폭 ±2px→±6px.
- 물음표 블록: 머리치기만 아이템이 나오던 걸 **내려찍기로도** 나오게 수정(빠져 있던 진짜 버그).
- 스위치·물음표 "띠용" 연출(§B4) + 안내 화살표(위=머리치기, 아래=내려찍기) 추가.
- 파일: `client/src/rooms/baseworld/BaseworldScene.ts`, `visualLanguage.ts`

### 2.2 이동 발판 로컬 시뮬레이션 + 캐리 (§14 원칙 적용)
- 문제의식(사용자 지적): 서버 왕복 지연 자체가 근본 문제인데 왜 서버 권위로 처리하냐 — 로컬에서 다 볼 수 있는데.
- **로컬 시뮬레이션**: 내가 밟고 있는 블록은 서버의 dead-reckoning 고스트 대신, 같은 규칙 엔진(`shared/behavior`)을 클라에서 직접 돌려 지연 없이 계산.
- **캐리(진짜 근본 원인)**: 발판이 움직인 만큼 위에 탄 플레이어도 리지드하게 같이 옮겨야 하는데 그 개념 자체가 없었음 — 지연 제거만으론 부족했고, 이걸 추가하고 나서야 통과 버그가 실제로 해결됨.
- 파일: `client/src/rooms/baseworld/BaseworldScene.ts`의 `stepBlockGhosts()`

### 2.3 웅크림 스프라이트 연출
- `netphysics/squash.ts`에 감쇠 스프링(`createSpring`/`stepSpring`) 신설 — 기존 `mySquash`(순간반응)와 별도 트랙.
- 나 + 원격 플레이어 전부 적용, 테두리·손 위치도 같이 스케일.

### 2.4 스위치 머리치기 미발동 — 근본 원인은 코드가 아니라 클리어런스
- 실측(사용자에게 콘솔 로그 요청 → `prevVy`가 한 번도 음수로 안 찍힘)으로 발견: sw1 밑 클리어런스가 1칸(64px)인데 플레이어 키(96px)가 더 커서, 크라우치 키(60.8px)로 점프해도 **첫 프레임에 이미 천장(스위치)과 겹쳐** 물리 엔진이 같은 틱에 상승속도를 0으로 꺾어버림 — `bonkHead`가 확인하는 `prevVy<0` 시점을 영영 못 잡음.
- **맵을 넓히지 말라는 사용자 지적**(테스트맵이라도 문제를 진짜로 고쳐야 함) → `avatar.ts`에 이미 있던 `ceilBonk` 이벤트(같은 틱에 점프가 천장에 막힘)를 `bonkHead` 판정에 추가 인정하는 걸로 해결. 맵은 원래 1칸 그대로 유지.

### 2.5 경사 벽 충돌 — 가장 여러 번 헤맨 부분 (필독)
사용자가 "경사 옆·밑면도 당연히 벽이어야 한다"고 요구해서 추가했다가, 봉우리를 넘는 순간 순간이동하는 버그를 **네 번** 잘못 짚고서야 진짜 원인을 찾음. 최종 원인과 수정만 기억하면 됨:

- **진짜 원인**: 경사 벽(`shared/physics/body.ts`)이 "벽 쪽으로 이동 중인지"를 안 보고 무조건 밀어냈음. 봉우리를 넘어 반대쪽(벽 반대 방향)으로 걸어나가는 순간에도 몸통 절반이 아직 벽 x좌표에 걸쳐 있으면 "침입"으로 오판해서 몸을 벽 쪽으로 순간이동시켰음 — 그 자리가 두 경사 사이 빈 틈 위 공중이라 낙하까지 겹쳐 보였음.
- **최종 수정**: `movingIntoWall`(벽 쪽으로 이동 중인지 속도 방향) 조건을 추가 — 벽에서 멀어지는 방향으로 움직이는 몸은 절대 안 건드림. 이게 진짜 벽 충돌의 정의.
- **틀렸던 시도들**(순서대로, 왜 안 됐는지 — 다음에 비슷한 문제 만나면 이 순서를 반복하지 말 것):
  1. 관대한 스냅(12px 미리 당김) 제거 → 도움 안 됨(문제의 본질이 아니었음)
  2. `onSlopeDir` 이력(직전 틱까지 이 경사를 탔는지) 기억 → 봉우리가 맞닿은 경우만 해결, 틈이 있으면 여전함
  3. "높이 6px 이내면 봐준다" → 틈을 자유낙하로 건너는 데 몇 틱 걸려서 그사이 6px 넘게 떨어지면 무효
  4. 판정 순서를 대각선 스냅 먼저 → 벽 나중으로 바꿈(`onSlopeDir===0`일 때만 벽) → 근본적으로 방향을 안 보는 문제라 여전히 실패
  5. **(최종)** 속도 방향 조건 추가 → 해결
- 파일: `shared/physics/body.ts`, `shared/physics/terrain.ts`(`Slope.faces` 옵션), `client/src/rooms/baseworld/visualLanguage.ts`(`drawSlopeBorder`)

### 2.6 물음표 블록 내려찍기 → 아이템 중력 낙하
- 머리치기=원작처럼 위에 뜬 채 등장, **내려찍기=중력 받아 떨어져서 바닥에 착지**.
- `ItemInstance`에 물리 바디를 새로 추가(`stepItemPhysics`), 서버 틱마다 스텝. 기존 정적 아이템(it1~3)은 그대로 안 움직임.
- 파일: `shared/parts/item.ts`, `server/src/rooms/base/PhysicsRoom.ts`

### 2.7 고아 스프라이트 버그 (여러 증상의 공통 원인이었음)
- **증상들**: "밟으면 사라지는 블록이 사라져도 회색 스프라이트가 남음", "스위치로 숨긴 블록이 물리판정은 없어졌는데 스프라이트는 남음", "띠용 연출할 때 원래 스프라이트도 같이 남음" — 전부 같은 원인.
- **원인**: `onAdd` 콜백이 기존 오브젝트를 파괴 안 하고 새로 `set()`만 함. Colyseus는 콜백 등록 시점에 이미 존재하는 항목 전부에 대해서도 `onAdd`를 다시 쏘기 때문에, 씬 재시작/재연결 시 새 오브젝트가 하나 더 생기고 예전 건 고아로 남아 화면에 계속 보임.
- **수정**: `players`/`monsters`/`projectiles`/`items`/`carryables`/`blocks` 전부 onAdd에서 "새로 만들기 전에 기존 것 파괴" 가드 추가.

### 2.8 아이템 스폰 즉시 자동습득 ("먹었는지 모르겠다")
- 스폰 유예(`TUNING.item.spawnGraceMs=350`) 추가 — 막 나온 아이템은 잠깐 보여준 뒤에야 먹을 수 있음. `itemSpawnAt` 맵으로 스폰 시각 추적, 클레임 체크에서 유예 중이면 스킵.

### 2.9 붕괴 예고 연출 재설계
- 처음엔 "금 가는" 크랙 라인을 그렸는데 두 번 반려됨: (1) 정사각형 가정하고 짬(경사·비정형 그림에서 부자연스러움), (2) 연출 자체가 별로.
- **최종**: 도형에 전혀 의존하지 않는 방식 — 테두리 지글거림(둘레를 짧은 구간으로 쪼개 구간마다 다른 위상으로 떨림) + 머리 위 카운트다운 링(남은 시간을 파이 형태로 소진). 어떤 모양의 에셋이든 항상 통함.
- 파일: `client/src/rooms/baseworld/visualLanguage.ts`의 `drawCrumbleWarning`/`drawSizzlingRect`

### 2.10 스위치 토글러/영향 블록 이중 테두리
- 원인: 일반 흰 실선 면 테두리와 회전 줄무늬/틴트 테두리를 **같은 블록에 둘 다** 그리고 있었음(사용자가 "블록이 여러 개 배치된 것 같다"고 표현한 게 이거였음).
- 수정: 자체 테두리가 있는 블록(switchToggler/switchAffected)은 일반 면 테두리를 스킵. switchAffected는 실체/유령 상태 무관하게 항상 점선+애니메이션으로 통일(전엔 실체화되면 실선으로 바뀌었음).

### 2.11 내려찍기 화면 흔들림이 다른 플레이어 착지에도 발동
- `feedback.poundLand`가 사운드+카메라 흔들림을 한 함수에 묶어놨는데, 원격 플레이어 착지 감지 지점에서도 그대로 호출해서 내 화면이 남의 착지에도 흔들렸음.
- `poundLandOther`(소리만) 신설해서 분리. 최신 커밋(`932f636`).

## 3. 스프라이트 렌더 시스템 (전 엔티티, 이미지 없이 완성해둠)

### 3.1 설계 원칙
- **로드 경로 하나**: 시스템 기본 에셋이든 유저 제작 에셋이든 클라는 항상 `GET /api/assets/:id` 또는 `/api/assets/by-name/:name`만 안다. 응답 형태(`AssetManifest`)가 유일한 계약.
- **액션 분류는 기존 카탈로그 재사용**: `shared/actions/catalog.ts`의 `idle/walk/onair/fly/climb/attack` 6종 그대로. 웅크림·슬라이드·내려찍기는 액션이 아니라 기존 squash/스프링 연출이 표현(카탈로그 방침 그대로 유지).
- **윤곽은 프레임별로** 추출·캐시(알파 채널 → Moore-neighbor 외곽선 추적 → Douglas-Peucker 단순화). 걷기 애니메이션이면 다리 움직임 따라 테두리도 프레임마다 바뀜.
- **폴백 = 항상 사각형**: 매핑 없음·시트 미생성·로드 실패·로딩 중이면 지금까지 쓰던 색 사각형+사각 테두리로 자동 후퇴. 강제 전환 없음.
- **면별 색 테두리를 임의 윤곽에 확장**: `drawPolyFaceBorders`(`visualLanguage.ts`)가 윤곽 폴리곤의 각 점을 바운딩박스에서 가장 가까운 변(위/아래/좌/우)으로 분류해서, 사각형이 4개 직선을 색칠하듯 윤곽선도 여러 색으로 나눠 그림. 몬스터의 "윗면 흰(밟기 가능)·옆아래 빨강(위험)" 같은 규칙이 그대로 적용됨. 히트박스(충돌)는 전혀 안 건드림 — 항상 사각형 그대로.

### 3.2 파일 구조
```
client/src/sprites/
  manifest.ts   매니페스트 타입
  load.ts       매니페스트 → Phaser 텍스처+애니메이션 등록 (로드 실패는 조용히 스킵)
  outline.ts    프레임별 윤곽 추출·캐싱
  resolve.ts    아바타/몬스터 상태 → 액션명
  view.ts       SpriteView — stepSpriteView(스프라이트 갱신)/getSpriteOutlineWorld(윤곽 폴리곤 반환)
  registry.ts   로컬 키(몬스터 asset명·아이템 kind·블록 성격) → 시스템 에셋 이름 매핑 + fetch 캐시

server/src/api/assets.ts             GET /api/assets/:id, /api/assets/by-name/:name
server/src/seed/ingestSpriteSheet.ts 로컬 PNG 시트를 기존 시스템 에셋에 ready로 직접 부착
```

### 3.3 이미 DB에 있는 시스템 에셋 (server/src/seed/systemAssets.ts)
새로 안 만들고 **재사용**해야 함 — 사용자가 "기본 아바타를 왜 따로 해놓냐, DB에 있어야지"라고 지적해서 이렇게 정리됨:

| DB name | registry.ts 로컬키 | 용도 |
|---|---|---|
| 졸라맨 | `avatar` | 아바타(나+원격 공용) |
| 굼바 | `goomba` | 몬스터 |
| 가시돌이 | `spiky` | 몬스터 |
| 가속 | `speed` | 아이템 |
| 거대버섯 | `sizeUp` | 아이템 |
| 기본 땅 | `ground` | 블록(기본) |
| 반통과 발판 | `platform` | 블록 |
| 가시 | `spike` | 블록 |
| 트램펄린 | `spring` | 블록 |
| 스위치 | `switch` | 블록 |
| 스위치 발판 | `gate` | 블록 |

TESTMAP에 있지만 시드에 없는 것(thwomp/chaser/shove/splitter 몬스터, invincible/hpUp 아이템, 돌)은 매핑이 없어서 자동으로 폴백 유지 — 에셋 생기면 `systemAssets.ts` 시드 추가 + `registry.ts` 매핑 한 줄이면 끝.

### 3.4 시트 받으면 할 일
액션별 PNG(가로 스트립, 투명 배경) + `manifest.json`(`{action: {file, frameCount, frameW, frameH}}`)을 한 폴더에 놓고:
```
npm run -w server ingest-sprites -- "<DB name>" <폴더경로>
```
코드 수정 없이 바로 게임에 반영됨. 여러 액션을 나중에 따로 채워도 됨(멱등 upsert).

### 3.5 검증 안 된 것 (실제 시트로 한 번도 안 돌려봄)
- `outline.ts`의 알파 임계값(40)·단순화 오차(1.4px) — 실제 그림체에 따라 튜닝 필요할 수 있음
- `load.ts`의 프레임레이트 계산(`frameCount / durationSec`)
- Phaser `AnimationFrame.textureFrame` → outline 캐시 인덱스 매칭이 실제로 프레임 번호와 일치하는지
- 몬스터 `currentAction`→액션 매핑(`resolve.ts`의 `MONSTER_ACTION_MAP`)이 실제 재생 시 부자연스럽지 않은지

## 4. 착수 안 한 것 (전수조사 C 목록, 이번 세션 범위 밖 — 그대로 남음)

- 등껍질(shellify) 완전 구현
- 몬스터 스톰프 반응(die/stun/hurtAttacker/trampoline/shellify) 값별 실제 분기
- 발사체-몬스터 충돌
- 던진 물체 재잡기
- dead behavior 액션(stretch/revive/returnUp/lavaBounce/knockbackPlayer/bouncePlayer/splitOnDeath) 정리 — 살릴지 삭제할지 미정
- `BlockSpec.seesaw`/`pushable` 존치 여부 미정
- 트램펄린 옆면 넉백 — **결정만 됨(옆면은 넉백 수준으로 충분), 코드 미적용**. `knockback`+`trampoline` 물성을 한 블록에 같이 넣으면 되는데, `properties` 배열 순서가 실제 힘 계산에 영향 줌(나중 항목이 먼저 항목을 덮어씀) — 반드시 `[knockback, trampoline]` 순서로. 테두리는 배열 순서 무관하게 항상 맞게 그려짐(코드가 이미 그렇게 짜여 있음, 재검증 불필요)
- 숨김 블록 점선 테두리 애니메이션 — 이미 구현됨(§2.10), 추가 작업 없음

## 5. 알려진 미해결 버그

- "일반 블록이 밟으면 사라지는데 회색 스프라이트가 남는다"는 초기 리포트 — §2.7(고아 스프라이트) 수정으로 해결됐을 가능성 높지만 **재확인 안 됨**. 재현되면 어떤 블록인지 특정해서 알려줘야 함
- 트램펄린 옆면이 파랗게 보이는 문제 — 코드상 색 언어 규칙엔 없어서, 모든 블록 공통 기본 채움색(청회색이었던 것)을 순회색으로 바꿔서 완화 시도함. 원인이 진짜 이거였는지 미확인

## 8. 함정 모음

- **판정 버그는 "왜 안 되지" 상태로 여러 번 잘못 짚기 쉽다** — §2.5처럼 사용자에게 직접 콘솔 로그를 요청해서 실측하는 게 코드만 읽고 추측하는 것보다 훨씬 빠르게 원인을 찾았다. 막히면 이 방법 먼저 써볼 것.
- **맵을 고쳐서 버그를 회피하지 말 것** — 사용자가 두 번이나 "맵을 왜 바꾸냐, 코드로 고쳐야지"라고 지적함(§2.4, §2.5). 테스트맵이라도 물리/판정 버그는 물리/판정 코드에서 고치는 게 원칙.
- **`properties` 배열은 순서 의존** — 여러 물성을 한 블록에 넣을 때 나중 항목이 같은 축의 힘을 덮어씀. 테두리 색은 순서 무관(별도 파생 로직이라).
- **`onAdd` 콜백은 항상 기존 오브젝트 파괴 후 재생성** — Colyseus가 콜백 등록 시 기존 항목 전체에 onAdd를 다시 쏘기 때문에, 이 패턴을 안 지키면 고아 오브젝트가 계속 쌓인다. 새 엔티티 타입 추가할 때 반드시 이 패턴 따를 것.
- **사용자는 격식체·비속어 없는 존댓말을 기대하지만 피드백 자체는 매우 거칠게 옴** — 내용에만 집중해서 침착하게 대응할 것. 코드 작업은 명시적 "승인" 받고 시작(이번 세션 내내 이 규칙 유지됨).

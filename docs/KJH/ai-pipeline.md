# AI 생성 파이프라인 명세

> 확정 흐름: 유저 그림 + 설명 → LLM 1회 호출(액션별 영어 프롬프트 JSON)
> → 영상 생성(ComfyUI, 액션당 1클립) → 후처리 정규화 → 스프라이트 시트 → 게임.
> 해상도: 256~512px로 생성 → 64px 그리드로 nearest 다운스케일 (실측 검증 완료 — 저해상도 직접 생성은 품질 급락).

## 1. 입력 정규화 (제출 시)

- 그림판 원본(256×512, 투명 배경)만 입력 — 이미지 업로드는 제거됨 (2026-07-10).
  따라서 입력은 항상 투명 배경이 보장되며 배경 제거 ML 단계 불필요
- **불투명 bbox를 가로 중앙 정렬 + 바닥 스냅** (아바타·에셋 공통)

## 2. LLM 프롬프트 생성 (1회 호출)

- 고정 시스템 프롬프트(영어) + 유저 설명(언어 무관) + 필요 액션 목록
- 출력: `{ "idle": "...", "walk": "...", "onair": "..." }` (액션별 영어 영상 프롬프트)
- 고정 지시부에 반드시 포함 (2026-07-10, 스프라이트 안정화 방어):
  `single character, plain background, side view, full body,
   static camera, walking in place, no forward movement, seamless loop`
  — 걷기는 제자리걸음으로 생성. 실제 이동은 게임 코드 담당

## 2.5 배경색(크로마키) 자동 선택 ★ (2026-07-10)

영상 모델은 알파 출력 불가 → 배경을 일부러 채워 생성하고 나중에 제거한다.

- **키 색상 선택**: 그림의 불투명 픽셀 색(테두리 픽셀 가중)과
  후보 색(순녹/마젠타/시안/순청)의 HSV 거리를 계산해 **가장 먼 후보** 채택.
  경계 안티앨리어싱 띠가 살아남으려면 테두리-배경 거리가 커야 함.
  팔레트가 고정 그리드(~120색)라 거리 계산이 유한·예측 가능
- **프롬프트 주입**: `solid pure {color} background, flat, no gradient` +
  캐릭터에 해당 색 금지(네거티브)
- **제거 시 실측 샘플링**: 디퓨전은 지시색을 미묘하게 틀어 그림 →
  각 프레임 네 모서리 픽셀 중앙값을 실제 배경색으로 삼아 거리 임계값 제거
- **디스필**: 경계에 남는 키 색 기운 제거 (표준 후처리)
- rmbg류 ML 세그멘테이션과 병용 가능: 1차 크로마키(결정적) → 잔여물 ML 보정.
  주력은 5080 실험으로 결정

## 3. 영상 생성

- 액션당 1클립 (아바타·몬스터 = 3액션, 장애물 등 = 필요 시 idle 1개)
- 비동기 잡 큐. 상태: queued → generating → ready | failed
- 유저는 대기 없이 다른 작업 계속 (제출 즉시 화면 이탈)

## 4. 후처리 정규화 ★ (2026-07-10 — 생성물 불안정 교정)

관측된 문제: 루프 불연속, 액션 간 시작 위치 상이, 프레임 간 크기 변동.
영상 디퓨전의 본질적 특성이므로 생성물을 교정한다:

```
클립 → 프레임 추출 → 프레임별 배경 제거 → ①②③ → 8프레임 샘플 → 시트 패킹
```

> **bbox 구현 (2026-07-10 확정)**: ML 탐지 아님. 배경 제거 후 알파 채널
> 픽셀 스캔 — `alpha > 임계값(10~25)`인 픽셀의 min/max 좌표. 결정적, ms 단위.
> 노이즈 방어: 전체 불투명 면적의 1% 미만인 연결 요소는 무시
> (공중부양 그림의 분리된 덩어리는 보존됨).

1. **바닥-중앙 앵커링 (부분 보간)**: 프레임마다 불투명 bbox의 하단-중앙점을
   고정 좌표에 정렬한다. 단, 목표값으로 **완전 스냅하지 않는다** — bbox가
   노이즈·경계 오검출로 틀리면 프레임이 홱 튀기 때문. 대신 `원래값`과
   `보정목표값` 사이를 선형보간(lerp) 계수 α로 부분 이동한다:
   `new_pos = lerp(orig_pos, target_pos, α)`. α는 잠정 0.75(보정 쪽에 가깝게)이며
   bbox 정확도를 실측하며 조정한다. 효과: bbox 정확 시 거의 정렬,
   부정확 시 오차 영향이 (1-α)로 감쇠 → 지터 완화. α=1.0이면 기존 완전 스냅과
   동일(즉 기존 동작의 일반화). 이로써 모든 프레임·모든 액션이 같은 발 위치를
   공유하고, 전진 걷기가 나와도 제자리걸음으로 수렴한다
   (프롬프트 방어와 이중 안전망)
2. **스케일 정규화 (부분 보간)**: idle 클립의 중앙값 bbox 높이 = **기준 키**.
   전 액션 전 프레임을 기준 키로 보정하되, 앵커링과 마찬가지로 완전 스냅이 아니라
   부분 보간한다: `new_scale = lerp(orig_scale, target_scale, α)` 후 프레임당
   클램프(잠정 ±10% — 숨쉬기 등 정상 변화는 보존). bbox 부정확 시 스케일 오차도
   (1-α)로 감쇠되어 크기 지터가 완화된다. 기준 키가 히트박스 산출 입력이 됨
   (아바타: 1.3~1.95타일 클램프 → assets.hitbox_h_px)
3. **루프 구간 자동 선택**: 프레임 간 유사도(MSE/pHash)로 첫·끝이 가장 닮은
   부분 수열을 루프로 선택

한계(수용): 미세 떨림 잔존 — 64px nearest 다운스케일이 상당 부분 흡수,
잔여분은 손그림 애니메이션의 보일링 느낌으로 수용.

## 4.5 후처리 파라미터 (JSON 외부화) ★ (2026-07-11)

후처리 수치를 코드에 하드코딩하지 않고 설정 JSON 하나로 뺀다.
코드 수정 없이 튜닝 가능하고, 팀 소통도 이 파일 기준으로 한다.

```json
{
  "anchor": { "lerp": 0.75 },
  "scale":  { "lerp": 0.75, "clampPerFrame": 0.10 },
  "bbox":   { "alphaThreshold": 18, "minBlobRatio": 0.01 },
  "loop":   { "frames": 8, "similarity": "phash" },
  "chroma": { "candidates": ["green","magenta","cyan","blue"], "despill": true }
}
```

- `anchor.lerp` — 4절 ① 바닥-중앙 앵커링의 보간 계수 α (실측 후 확정)
- `scale.lerp` — 4절 ② 스케일 정규화의 보간 계수 α (실측 후 확정)
- `scale.clampPerFrame` — 4절 ② 프레임당 스케일 변화 클램프 한계(±10%)
- `bbox.alphaThreshold` — 4절 bbox 산출 시 불투명 판정 알파 임계값 (실측 후 확정)
- `bbox.minBlobRatio` — 4절 bbox 노이즈 방어: 무시할 연결 요소 최소 면적 비율(1%)
- `loop.frames` — 4절 ③ 루프로 샘플링할 프레임 수(8)
- `loop.similarity` — 4절 ③ 루프 구간 선택 유사도 척도(pHash)
- `chroma.candidates` — 2.5절 크로마키 후보 색 팔레트
- `chroma.despill` — 2.5절 디스필(경계 키 색 기운 제거) 사용 여부

실측으로 확정할 값: `bbox.alphaThreshold`, `anchor.lerp`·`scale.lerp`(α)
— bbox 정확도 측정 후 확정.

## 5. 발사체·스킬 이펙트

- AI 생성 없음. 유저의 1×1 이하 정지 이미지 + 코드 회전 (기본 탄 몇 종 제공)

## 6. 인프라

- LLM·GPU 호출은 서버 전용 (키 비노출)
- GPU: KCloud 3090(서빙) / 개인 5080(워크플로우 개발) — 실측 후 역할 교체 가능
- 폴백: 생성 실패·지연 시에도 기본 에셋으로 게임 루프 유지

## 7. 담당·접점 (2026-07-11)

스프라이트 가공(정규화·크로마키·시트 패킹)은 KJH 담당, 영상 생성·ComfyUI·LLM은
LSJ 담당이다.

⚠️ **접점(미해결)**: 팀원 Qwen 게이트웨이가 현재 "단일 wan_prompt"만 생성한다.
그러나 우리 파이프라인은 "액션별(idle/walk/onair) 프롬프트 → 액션별 영상 → 가공"이
필요하다. 액션별 프롬프트 분리를 LSJ와 규격 합의해야 한다.

## 8. 인프라 토폴로지 확정 + 생성 파이프라인 (2026-07-13)
(§6의 GPU 역할 잠정 노트를 대체)

| 구성요소 | 위치 | 역할 | 네트워크 |
|---|---|---|---|
| LLM (Qwen) | 3090 ML 서버 | 슬롯별 프롬프트 생성 | 캠퍼스 내부(VPN 안) |
| ComfyUI | 5080 개인 컴퓨터(대구) | 애니메이션(스프라이트) 생성 | 외부 — VPN으로 접속 |
| 게임 서버 + DB + 터널 | KCLOUD VM(172.10.7.247) | 백엔드 | 캠퍼스 내부(VPN 안) |

**핵심 제약**: ComfyUI 워커가 외부(집 PC, NAT 뒤) → 백엔드가 잡을 **push 불가** → **pull 방식**.
- 워커가 큐를 폴링(또는 워커가 먼저 여는 롱커넥션)으로 잡을 가져감. **모든 연결은 워커→백엔드 방향**(폴링·업로드).
- **프롬프트는 백엔드가 잡 적재 시 3090 LLM을 호출해 잡에 실어둠** → 5080 워커는 `(원본 그림 + 슬롯 + 프롬프트)`만 받아 ComfyUI 실행(워커는 LLM 몰라도 됨).
- 결과 시트는 워커가 백엔드/스토리지로 **업로드** → `AssetSprite.sheetUrl` 채움.

**데이터 흐름**:
```
파츠 저장 → 백엔드: collectSlots(attrs.rules) → 슬롯 목록
  → 백엔드: 슬롯별 3090 LLM 프롬프트 생성 → AssetSprite(queued, prompt 포함) 적재
5080 워커(VPN): 큐 폴링 → 잡 claim → ComfyUI 실행 → 시트 업로드 → AssetSprite(ready)
게임: AssetSprite.slot 으로 로드 (실패·미완성은 기본 에셋 폴백)
```

**담당 정정**: ComfyUI/GPU 워크플로우 = KJH(5080 개인). LLM 게이트웨이(프롬프트) = LSJ(3090).
§7의 "액션별 프롬프트 분리" 접점은 유지 — 이제 "슬롯별 프롬프트"로 규격 합의 필요.

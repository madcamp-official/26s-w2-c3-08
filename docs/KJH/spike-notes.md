## 목적

세션에서 "가능하다"고 주장만 했던 두 가지 기술 리스크를 실증:
1. Phaser **Arcade 물리에서 커스텀 램프 로직**으로 경사면 + 슬라이딩 구현
2. **1×2 스프라이트 상체/하체 분할 스쿼시** 연출 (추가 스프라이트 생성 없이)

## 2차 수정 (2026-07-10, 유저 플레이 피드백 반영)

유저 직접 플레이에서 발견된 문제와 수정:

| 증상 | 원인 | 수정 |
|---|---|---|
| 슬라이드 중 경사 끝에서 수평 활공 | 접지 중 vy=0으로 리셋되어 내리막에서 표면이 발보다 빨리 내려가면 접지 해제 | **접지 유지(ground stickiness)**: 직전 프레임 접지 시 발 주변 표면에 부착 |
| 바닥 꺼짐(고속 낙하) | 재착지 창(±4px)을 한 프레임에 건너뜀 (터널링) | **스윕 크로싱**: 직전~현재 발 위치 사이에 표면이 있으면 착지 |
| 최고속(520) 45°에서만 재발 | 접지 유지 여유폭이 비대칭(위 8px 고정) — 표면 하강 8.7px/frame > 8px | 여유폭을 **양방향 대칭 + 속도 비례**(`|vx|·dt·2+12`)로 |
| 상하체 분리·바닥 겹침 | Phaser `setCrop`은 원본 프레임 위치 유지 (하체가 64px 아래에 그려짐) | 상/하체를 **별도 텍스처**로 분리 |
| 점프/착지 스쿼시 방향 반대 | — | 점프=하체가 위로 눌림, 착지/밟힘=상체가 아래로 눌림 (허리 기준 배치) |
| 타일이 가로로 찌그러짐 | flexbox가 캔버스 CSS 폭만 축소 (비균등 스케일) | `Phaser.Scale.FIT` + 64px 그리드 오버레이 |

추가된 사양 (player-spec 반영 대기 중 실험값):
- 슬라이드 가속 3200px/s² (최고속 520 도달 ~0.16초, 유저 요청 "빠르게 한계속도 도달")
- 웅크리기: 총 키 **0.95타일**로 압축, 상체 62% / 하체 38% 배분 (하체가 더 줄어듦)
- 기본 키 가변: **1.65~1.95타일** 범위 (스파이크에선 숫자키 1/2/3 = 1.65/1.80/1.95 전환)
- 자동 검증 6/6 통과: 45°·완경사 최고속 슬라이드 추적 오차 0, 공중 이탈 0,
  종료 후 평지 정지, 점프 이탈, 경사 오르기, 웅크리기 높이

## 구현 노트 (본 구현 시 참고)

1. **접근법**: Arcade 중력·충돌을 끄고 지면(평지+경사)을 수동 판정.
   경사 표면 y = 크기 박스 대각선의 선형 보간 — asset-attributes.md의
   "기울기는 크기에서 자동 유도" 설계가 코드 그대로 대응됨.
   본 구현에서는 일반 타일은 Arcade 충돌을 쓰고 경사 타일 구간만
   이 램프 로직으로 오버라이드하는 하이브리드가 적절.
2. **⚠️ 발견된 함정 — 지형 겹침**: 완전충돌 평지와 경사 구간이 겹치면
   평지 판정이 먼저 잡혀 순간이동이 발생. **에디터 배치 규칙으로
   "경사 타일과 다른 충돌 타일의 그리드 겹침 금지"를 강제해야 함**
   (에셋 속성 문서에 반영할 것).
3. 슬라이딩 방향은 경사 dir에서 유도(up-right=왼쪽 내리막). 슬라이드 중
   경사를 벗어나 공중에 뜨면 상태 유지 후 재착지 시 재판정 — 자연스러움.
4. 스쿼시는 `setCrop` 2장 + scaleY + 발 기준 y 재배치로 충분.
   컨테이너/셰이더 불필요.

## 개발 환경 주의

- Claude 브라우저 페인은 `document.hidden=true`라 RAF가 멈춤 →
  Phaser가 프레임 0에서 정지. **자동 테스트는 `game.loop.step(t)` 수동
  호출로 동기 구동**하면 됨 (이번 검증 방식). 실제 브라우저에서는 무관.
- 한글 경로의 파일은 Git Bash에서 인코딩 문제 발생 → PowerShell로 복사 후 처리.

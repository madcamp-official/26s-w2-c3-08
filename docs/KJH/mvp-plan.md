## 게임 플레이 (여덟째 항목)

- 모든 플레이어는 병합 맵의 **가장 첫 시작지점에서 출발해 끝 지점까지 레이싱**.
- 기본 플레이 시간 **5분**, 도착 시간 기록.
- 검증 실패 패널티:
  - 원 요구사항: 도착 시간 **+15초**
  - **MVP 기본 결정: 레이스 시작 시 15초 freeze** (구현 단순, 체감 즉각)
  - 원 요구사항으로 되돌리려면 이 항목만 변경하면 됨
- 5분 내 완주자가 없으면 **+30초 연장**. 연장 중에는 각 플레이어의 현재 가로
  위치를 세로선으로 표시(누가 앞인지 직관화).
- 순위: 완주자 도착 시간 오름차순 → 미완주자는 최종 끝지점과의 거리 가까운 순.

## 4. 사용자 플로우

1. **로그인**: 닉네임만 입력. 회원가입/OAuth 없음. 서버가 임시 user_id 발급.
2. **로비**: 공개방/비공개방 목록. 공개방은 비번 없이, 비공개방은 비밀번호 입장.
   "공개방 빠른 입장" = 입장 가능한 공개방 무작위 연결.
3. **제작 (3분)**: 자기 맵 조각 제작.
   - 좌측: 에셋 창고 (기본 제공 / 사용자 제작 구분. 유형: 장치·지형·적군·아이템·배경)
   - 상단: 자주 사용/고정 에셋
   - 중앙: Phaser 캔버스
   - 우측: 선택·이동·삭제·확대축소 최소 도구
4. **검증 (2분)**: 제작 종료 시 맵 잠금. 본인 맵을 직접 플레이해 시작→끝 도달.
   - 성공: 해당 세그먼트 `validated`
   - 실패: 최종 레이스 시작 시 15초 freeze 패널티
   - 검증은 제작 종료 시점 스냅샷 + `segment_hash` 기준 (검증 후 변조 방지)
5. **병합**: 성공한 세그먼트만 무작위 순서로 연결. 이전 세그먼트 끝점 ↔ 다음
   시작점 연결, X뿐 아니라 **Y 오프셋도 반영**. 단 `end.y - start.y` 범위 제한
   (카메라·난이도 안정성). 성공 세그먼트가 0개면 **기본 제공 세그먼트로 레이스
   무조건 진행**.
6. **레이스 (5분 + 연장 30초)**: 위 게임 플레이 규칙대로.

## 5. 기술 스택

| 레이어 | 선택 | 역할 |
|---|---|---|
| 프론트 | **Vite + React + TypeScript + Phaser + Zustand** | React=로그인/로비/도감/AI 폼/결과/HUD, Phaser=캔버스·물리·에디터·레이스, Zustand=클라 전역 상태 |
| 백엔드 | **Node.js + Express + Socket.IO + TypeScript** | Express=REST(세션·에셋·방·세그먼트), Socket.IO=실시간(페이즈·타이머·좌표·결과) |
| 실시간 | Socket.IO (WebRTC 배제 — P2P/STUN/TURN은 MVP에 과함) | 서버 중심 중계 |
| DB | **PostgreSQL + Prisma** | 타입 연동. REST/Socket payload는 **Zod 검증** |
| 파일 | MVP: 서버 업로드 디렉터리/정적 저장 → 고도화 시 S3/R2/MinIO | |
| AI | **서버에서만 호출** (키 노출 금지). 유저 제출 → OpenAI API로 프롬프트 정리 → 내부 GPU(WAN) 서버에 비동기 Job → DONE/FAILED | 생성 지연 중에도 기본 에셋으로 게임 진행 가능해야 함 |

## 6. 주요 데이터 모델 (계획서 안)

- **User**: id, nickname, avatar_asset_id, race_penalty_ms (임시 사용자)
- **Asset**: id, owner_id, type, sprite_url, placement_cost, collider_type,
  width_cells, height_cells, status
  - 원칙: **AI 이미지는 시각 표현일 뿐, 충돌은 collider_type + 셀 크기로 처리**
- **MapSegment**: id, room_id, creator_id, start_point, end_point, assets(배치
  ID+그리드 좌표), segment_hash, is_validated
- **Room**: id, is_public, password_hash, phase, players, max_players,
  phase_ends_at — **페이즈는 서버가 관리**, 클라는 전파받아 화면 전환

## 7. 핵심 API / Socket 이벤트

REST:
- `POST /session` 닉네임 임시 세션
- `GET /assets` 기본+내 에셋
- `POST /assets/generate` AI 생성 Job 등록
- `GET /rooms`, `POST /rooms`, `POST /rooms/:id/join`
- `POST /rooms/:id/segments` 세그먼트 제출

Socket:
- `room:joined`, `phase:changed`, `timer:tick`
- `segment:submitted` (제출 상태 공유), `validation:result`
- `race:position` (좌표 브로드캐스트), `race:finished`, `results:final`
- 시간 조정 투표 이벤트 (8절 참조)

## 8. MVP 규칙과 제한

- **그리드 64×64px 고정** (2026-07-10 개정: 원안 32px → AI 생성 이미지의 디테일
  보존을 위해 64px로 상향. nearest 정수배 스케일 전략 유지), 충돌 에셋은 그리드 스냅 강제
- 시작점·끝점: 삭제/복제 불가, 그리드 단위 이동만 허용
- 맵 최대 폭·높이 제한, 세그먼트 Y 시작-끝 차이 제한
- **시간 추가/단축은 1인 1표 투표**: 과반 찬성 시 ±15초, 페이즈당 최대 1회
- 검증 실패 패널티는 "레이스 시작 15초 freeze"로 통일

## 9. 리스크 관리

1. **AI 생성 지연** → 기본 에셋 품질·수량 충분 확보 (지형 타일, 점프 발판,
   장애물, 배경, 시작점, 끝점, 단순 적군). 생성 실패·지연에도 핵심 루프 유지.
2. **물리 버그** → 자유 배치 금지(그리드 스냅), 복잡한 회전·비정형 충돌체·
   경사면·움직이는 플랫폼 최소화. 사각형 충돌체 위주.
3. **멀티 동기화** → 서버 권위 물리는 일정상 부담. **MVP는 클라이언트 권위 +
   서버 좌표 중계**. 치팅 방지를 포기하고 시연 완성도 확보.

## 11. 테스트 계획

- 방: 공개/비공개 생성, 비번 오류, 빠른 입장, 최대 인원
- 페이즈: 로비→제작→검증→병합→레이스→결과 자동 진행
- 에디터: 그리드 스냅, 비용 제한, 시작/끝점 삭제 불가, 잠금 후 수정 불가
- 검증: 성공 validated=true, 실패 패널티 적용
- 병합: 서로 다른 Y값 맵이 끊김 없이 연결
- 레이스: 좌표 브로드캐스트, 완주 기록, 30초 연장, 미완주 거리순 정렬
- AI: 성공/실패/지연 상태 모두에서 기본 에셋으로 게임 진행 가능

## 12. 최종 성공 기준

- 실행 가능한 웹 앱. **최소 2명이 같은 방에서 제작→레이스 결과까지 1게임 완료**.
- AI 생성은 시연 가치가 있으면 좋지만, 실패·지연 시에도 기본 에셋 루프는 반드시 동작.
- 본질: "AI로 만든 재료와 사용자가 만든 맵이 실제 멀티플레이 레이스로 이어진다"는
  경험의 증명.

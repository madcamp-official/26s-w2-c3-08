## 1. 이 게임은 무엇인가

**슈퍼 마리오 메이커에서 영감을 받은 웹 기반 멀티플레이어 레이스 게임**이다. 핵심은 세 가지가
맞물린다:

1. **유저가 직접 그린다** — 브라우저 안 페인트 툴로 캐릭터·몬스터·발판 등 에셋을 그린다.
2. **AI가 살아 움직이게 한다** — 그린 그림을 AI(로컬 LLM + ComfyUI, GPU)가 스프라이트
   애니메이션(idle/walk 등)으로 만든다. **"유저가 그린 것이 AI로 살아난다"가 이 게임의 강점.**
3. **다 같이 달린다** — 각 유저가 맵의 한 "라인(세그먼트)"을 만들고, 그 세그먼트들이 **랜덤으로
   병합**되어 하나의 큰 맵이 되며, 모두가 그 맵을 **레이스**하면서 서로 **밀고 머리를 밟는 PvP**를 한다.

**전반적으로 마리오(특히 마리오 메이커)를 베끼는 방향**이다. 조작감·적 행동·블록 규칙 등은
원작 로직을 최대한 따르되, 원작이 공개하지 않은 세부 수치(px·속도·시간)는 우리가 튜닝으로 맞춘다.

**팀 구성 (2주 프로젝트)**: KJH = 게임 클라이언트 + 스프라이트 생성·가공. LSJ = AI 파이프라인 +
백엔드 + 일부 프론트엔드. 이 문서와 물리 설계는 KJH 담당 영역이다.

## 2. 유저가 게임을 즐기는 전체 흐름

### 2-1. 제작 단계 (게임 밖)
1. 유저가 페인트 툴로 에셋을 그린다 (캐릭터 아바타, 몬스터, 발판, 장애물, 배경 등).
2. 에셋마다 **속성**을 고른다 — "이 몬스터는 어떻게 움직이나(패턴)", "무엇에 죽나(취약성)",
   "이 블록은 무엇에 부서지나" 등. (§6 에셋 속성 시스템)
3. AI가 그림을 애니메이션 스프라이트로 변환한다 (idle/walk 등, GPU에서 생성).
4. 유저가 자기 맵 **세그먼트("라인")**를 만든다 — 지형·발판·몬스터·아이템을 배치.

### 2-2. 플레이 단계 (게임 안)
5. 여러 유저의 세그먼트가 **랜덤 병합**되어 하나의 레이스 맵이 된다.
6. 모두 같은 맵의 시작점에서 출발해 **완주를 향해 달린다.**
7. 달리는 동안:
   - **조작**: 이동·달리기·점프·웅크리기·슬라이딩·내려찍기·벽점프·벽타기·공중스핀 (마리오식)
   - **PvP**: 서로 **밀고**, 상대 **머리를 밟고**, 물체를 **잡아 던져** 방해한다.
   - **월드**: 몬스터를 밟거나 피하고, 파괴형 블록·이동 발판·장애물을 헤쳐나간다.
   - **아이템**: 거대버섯(커지고 생명+1), 가속, 스타(무적) 등.
8. **생명/부활/완주** 규칙에 따라 순위가 갈린다.

> ⚠️ **"게임 시작 버튼 이후의 정확한 흐름"(로비→병합→레이스→부활→완주 규칙)은 아직 미정.**
> 사용자가 별도로 정리해 설명하기로 한 기획 영역이다. 위 6~8은 알려진 큰 그림일 뿐.

### 2-3. 방(Room)의 종류
게임은 상황별로 다른 "방"에서 돌아간다 (전부 같은 물리 뼈대를 공유):
- **로비/대기실**: 플레이어 목록을 보며 기다림. PvP·생명 없음, 걷기 정도.
- **레이스(실제 게임)**: 병합된 맵, 생명·부활·완주, PvP 전부.
- **맵 에디터 테스트**: 자기 세그먼트 하나만 단독 로드해 혼자 시험(즉시 리스폰).
- **baseworld**: 규칙 없는 순수 물리 샌드박스. 개발·디버그용으로 계속 존치.

## 3. 지금까지 어떻게 진행해 왔나 (개발 여정)

이 설계가 왜 지금 모습인지 이해하려면 순서가 중요하다.

### 3-1. 1차 구현 — baseworld (서버 권위)
- 브랜치 `kjh/baseworld-netphysics`에서 **서버 권위 물리 샌드박스 + 개발자 콘솔**을 만들었다.
- 서버가 물리의 진실을 계산하고(고정틱 60Hz), 클라는 예측 + 서버 상태로 보정하는
  정통 방식이었다. 개발자 콘솔(백틱 토글)로 join/tp/tune 등을 쳤다.
- **KCLOUD VM에 배포**까지 성공했다 (cloudflared 터널로 공개 도메인, VPN 없이 접속 가능).

### 3-2. 결정적 발견 — 지연 305ms
- 대전 노트북 ↔ 대구 기숙사 데스크톱으로 **실제 원격 테스트**를 했더니, 입력→서버반영 왕복이
  **평균 305ms**였다.
- 이 지연에서는 서버 권위 + 오차 보정으로는 **조작감을 살릴 수 없었다** — 캐릭터가 끌리고
  순간이동하듯 튀었다. 대구에서는 렌더 버그로 플레이어가 아예 안 보이기도 했다.

### 3-3. 대전환 — 서버를 "중계기"로 격하
- 결론: **서버 권위를 포기.** 서버는 위치를 검증하지 않고 **중계(relay)만** 하고, **각
  클라이언트가 자기 캐릭터의 진실(로컬 권위)**을 갖는다. 그러면 지연과 무관하게 내 조작이 0ms로
  반응한다. 대가로 핵 방지를 포기한다(사용자 동의).
- 동시에, 기존 물리 코드가 **플레이어 전용**이라 몬스터·발판·블록 같은 다른 엔티티로 확장이
  안 된다는 구조적 한계도 드러났다.

### 3-4. 재설계 결정 — physics-generic
- 물리 + 방 구조를 **전부 삭제하고 새 브랜치 `kjh/physics-generic`에서 다시 짜기로** 했다.
- 이후 이 긴 설계 대화가 이어졌다: 범용 물리 엔진, 네트워크 철학, 눈속임(연출), 몬스터,
  잡기, 발사체, 에셋 속성 등을 하나씩 확정하며 [physics-generic-spec.md]에 축적했다.
- **작업 원칙**: 구현 전 디렉토리 구조를 먼저 전부 짜고, 사용자가 "승인"을 말한 뒤에만
  실제 코드를 작성한다. 결정은 즉시 문서에 기록한다.

## 4. 게임 시스템 — 조작과 물리 (마리오 베끼기)

### 4-1. 기본 이동·점프
- 걷기 / **달리기(Shift)** — 최고속이 달라짐.
- 가속·감속이 있고(관성), 공중에서는 제어력이 약간 줄어듦.
- **가변 점프**(누른 시간만큼 높이), 달릴수록 점프가 더 멀리·높이.
- **코요테 타임**(발판을 벗어난 직후 잠깐 점프 허용) + **점프 버퍼**(착지 직전 미리 누른 점프 인정).
- **코너 보정**: 발판 모서리에 살짝 못 미치면 끌어올려 착지시키고, 천장 모서리에 머리가 살짝
  걸리면 옆으로 밀어 통과시킨다. 원작의 관용 기능(버그 아님).

### 4-2. 특수 동작
- **내려찍기(그라운드 파운드)**: 공중 ↓ → 잠깐 공중 정지(초반 살짝 상승) → 수직 낙하. 정지 중
  스핀 애니메이션. 최소 높이 이상에서만 발동. 스핀으로 캔슬 가능, 경사에 착지하면 슬라이딩 전환.
- **웅크리기**: 히트박스가 실제로 줄어듦(낮은 틈 통과). 천장 아래선 못 일어남.
- **슬라이딩**: 경사에서 가속(상한 있음). 유효 입력은 점프뿐.
- **공중 스핀**: 낙하를 잠깐 늦춤. 공중 1회, 착지·벽점프·벽 슬라이드로 리셋.
- **벽점프 + 벽타기**: 벽에 붙으면 **낙하가 느려짐**(마리오식 낮은 상한 유지). 붙는 순간
  잠깐은 더 강하게 잡았다가 완화(2단계 상한). 벽점프로 반대쪽으로 튕겨 오른다.
- **트리플 점프는 없음. 지상 스핀 점프도 없음.**

### 4-3. 좌표·물리 기반
- 좌표 원점은 **바닥-중앙**(발 위치). 좌표는 연속(부동소수점).
- 충돌은 축분리 AABB + 경사 + **MTV(최소이동벡터)** 방식 — 벽에 끼어도 실제 겹친 만큼만 살살
  밀어내서, 예전의 "벽 순간이동" 버그가 원리적으로 안 생긴다.
- **압사(끼임) 즉사**: 양쪽에서 압박받아 밀려날 공간이 없으면 죽음(원작 쿵쿵 압사 재현).

## 5. 게임 시스템 — 네트워크와 "눈속임" (이 게임의 핵심 철학)

지연 305ms를 이기기 위한 설계가 이 게임의 가장 독특한 부분이다.

### 5-1. 하이브리드 권위
- **내 캐릭터** = 내 클라 로컬 권위 (0ms 반응). 조작감을 위해.
- **다른 플레이어** = 내 화면에선 **고스트**(서버가 받은 위치를 보간).
- **공유 오브젝트(몬스터·이동 발판·장애물)** = **서버 권위** (모두 같은 걸 봐야 하므로).
- 분류 원칙: **시간만으로 정해지는 것(고정 경로·주기·타이머) = 로컬 계산**,
  **플레이어에 의존하는 것(추적·스위치·트리거) = 서버**.

### 5-2. "당하는 쪽이 판정한다"
모든 상호작용(밀기·밟기·피해)의 통일 원칙:
> 공격하는 쪽은 자기 화면에서 **연출과 손맛만 즉시** 받고,
> 실제 피해/밀림은 **당하는 쪽이 자기 화면 기준으로** 확정한다.

- 장점: "나 안 부딪혔는데 밀렸다"는 억울함이 없다.
- 대가: "내 화면엔 맞췄는데 상대에겐 안 맞음" = 공격이 가끔 씹힘 (수용하기로 함).

### 5-3. 연출 2레이어 — 진짜 위치는 안 변하고 스프라이트만
게임의 "눈속임"이 여기 있다. 모든 상호작용을 두 층으로 나눈다:
- **연출 레이어** (스프라이트만 움직임, 실제 좌표·히트박스 불변): 자기 화면 접촉 시 항상
  재생. **상대의 실제 상태와 무관한 순수 시각 피드백**(선의의 거짓말 허용).
  - **자기 변형**: 밟히면 세로로 눌리고, 밀리면 가로로 찌부되고, 천장에 막힌 점프는 위로
    압축된다. 방향이 있는 변형이고, **원인이 지속되는 동안 유지, 사라지면 원복**(밀기=지속,
    천장점프=순간 — 규칙은 하나, 상황이 길이를 정함).
  - **rideOffset**: 밟은 사람은 밟힌 사람의 "쭈그러든 스프라이트 위"를 따라가 공중에 뜬 것처럼
    안 보이게 한다. 이동 발판 탑승도 같은 원리.
- **실제 상태 변경** (진짜 좌표·속도): 당하는 클라가 자기 화면 겹침일 때만.

### 5-4. 밀기·밟기·잡기의 로컬 처리
- **밀기**: 각자 "내 몸만" 상대 고스트에서 빠져나온다. 벽에 끼일 수 없다.
- **밟기**: 밟은 사람은 즉시 튕김·연출, 밟힌 사람은 자기 화면 판정.
- **잡기(§7)**: 로컬 즉시 잡되, 소유권만 서버가 확률로 중재.

## 6. 게임 시스템 — 몬스터와 적

### 6-1. 위치·어그로 (서버 권위)
- 몬스터 위치는 서버가 계산하고 **추측 항법(dead reckoning)**으로 부드럽게 보간한다
  (위치+속도를 보내 클라가 이어서 그림 → 지연이 가려짐).
- **어그로**: 가장 가까운 플레이어를 쫓되, 대상이 바뀌어도 **0.5초 뒤에 전환**(갈팡질팡 방지).
- **로컬 권위는 내 조작감을 위한 것이지 몬스터를 각자에게 맞추는 게 아니다** — 몬스터는 모두가
  같은 하나를 본다.

### 6-2. 죽음·HP (충돌 없는 방식)
- 즉사 몬스터: 밟은 클라가 죽음 확정 → 서버가 전원에 전파(멱등).
- **HP 여러 개 몬스터**(큰 쿠파 등): HP를 숫자 카운터가 아니라 **"독립 타격 이벤트의 집합"**으로
  둔다(포키 세그먼트 방식). 집합 합치기는 순서·중복에 안전해서, 여러 명이 때려도 합산 문제가
  없다. **무적 프레임**(피격 후 잠깐 무적)이 동시 타격을 막는다.
- 상태 전환(엉금→껍질), 밟기 불가(밟은 쪽 피해), 트램펄린화, 넉백 등 원작 반응을 지원.

### 6-3. 패턴과 선딜 (지연 흡수의 핵심)
- 몬스터는 **동작 패턴**(보행·추적·낙하돌진·회전·순간이동·발사 등) × **트리거**(상시·주기·접근·
  시선·스위치 등)를 조합해 만든다. 지형 무시 여부는 패턴에 고정.
- **선딜(예비 동작)이 지연을 흡수하는 마스터 장치다**: 액션 전 예비 동작을 하고, 그 시작 시
  서버가 "결과 + 실행 절대 시각"을 전파한다. 지연이 선딜 안에 흡수되어 실행 순간엔 모두가
  동시에 본다. 지연이 큰 클라는 **선딜 애니메이션을 빠르게 감아** 시각을 맞춘다. 선딜 길이는
  게임 감각 기준으로 짧게(0.2~0.8초).

## 7. 게임 시스템 — 잡기(carry)

- **K 키**로 잡는다(홀드=들고 있음, 릴리스=발사, 위 조합=위로 던짐). 나중에 키 재매핑 가능.
- 잡을 수 있는 건 **에셋 옵션**(유저 지정). 몬스터는 못 잡음(껍질 상태만 예외).
- **들고 있는 물체는 완전 무해**(그냥 이미지). 던지거나 놓는 순간에야 판정이 생긴다.
- **던진 직후 잠깐은 던진 사람 본인이 무시된다**(자책 방지).
- **손 연출**: AI가 아니라 **기본 제공 고정 손 스프라이트 1개**에 캐릭터 색을 계산해 입힌다.
  손은 물체 쪽으로 뻗고, 캐릭터가 움직이면 **살짝 늦게 따라오며 출렁(스프링)** — 우리 자체 연출.
- **네트워크**: 각자 로컬에서 즉시 잡는다(두 명이 같은 걸 잡는 순간이 생김). 서버가 **빠를수록
  당첨 확률이 높되 100%는 아닌 가중 확률**로 진짜 주인을 정한다(환경 나쁜 유저 배려). 진 쪽은
  잡기가 취소되지만, **그 전에 한 일은 원복하지 않는다.**

## 8. 게임 시스템 — 에셋 속성 (유저가 만드는 세계)

유저가 그린 에셋은 카테고리별로 속성을 고른다 (원문: `docs/KJH/asset-attributes.md`).
- **플랫폼**: 충돌면(완전/윗면만/일방통행), 실체화(항상/숨김/스위치/점멸), 이동(고정/왕복/밟으면
  이동), 모양(사각/경사), 접촉 반응(닿으면 낙하·소멸 후 **항상 재생**), 표면(미끄러움/컨베이어/
  트램펄린/대시).
- **파괴형 블록**: "파괴 가능" 지정 시, **아래서 머리치기·내려찍기·껍질·폭발** 중 무엇에 부서질지
  선택(위에서 밟기론 안 부서짐 — 원작대로). 부서져도 **무조건 재생**(소프트락 방지).
- **장애물**: 접촉 효과(대미지/즉사/튕김/상승기류), 판정 부위, 트리거, 이동·동작, 발사체.
- **몬스터**: 이동 유형, 추적, 절벽 반응, 밟기 반응, 생명력, 발사체, 분노·분열·불사 등.
- **취약성 매트릭스**: 각 몬스터가 무엇(밟기·내려찍기·껍질·스타 등)에 어떻게 반응하는지.
  유저는 3단 프리셋(약함/단단함/무적)으로 고르고, 세부는 고급 옵션.
- **아이템**(시스템 제공): 거대버섯(크기+생명), 가속, 스타(무적).
- **배경**: 충돌 없는 순수 장식.

**애니메이션 정책**: 모든 것이 **AI 스프라이트 애니메이션이 목표**(코드 연출은 최후의 임시
폴백일 뿐, 우리 강점을 안 깎기 위함). 생성 **우선순위는 절대적** — 1순위(idle/move)가 대기열에
남아 있으면 어떤 경우에도 다음 순위(공통 선딜 → 전용 이펙트)가 생성되지 않는다. 순수 이펙트
(폭발 섬광·발사체 궤적)도 궁극적으로 AI지만 최하위라 계속 밀릴 수 있다.

## 9. 코드·기술 구조

### 9-1. 스택
- **클라이언트**: Vite + React + TypeScript + Phaser(렌더·입력만) + Zustand.
  물리는 Phaser 물리엔진을 **안 쓰고** 직접 구현(서버와 같은 코드를 돌려야 하므로).
- **서버**: Node + Colyseus(방·상태 동기화) + Express.
- **공유(shared)**: 서버·클라가 함께 쓰는 순수 물리·타입 (Phaser·DOM 의존 금지).
- **DB**: MySQL + Prisma. **AI**: 로컬 LLM(vLLM) + ComfyUI, GPU 풀 모델 워커.

### 9-2. 예정 디렉토리 (physics-generic, 미착수)
```
shared/
  physics/    범용 엔진: tuning.json, body.ts(Body+MTV 충돌), terrain.ts(지형+파괴블록),
              interactions.ts(태그 기반 상호작용), index.ts
  entities/   엔진 위 콘텐츠: player/(state·controller·interactions), 향후 enemy·platform·
              obstacle·projectile
  maps/       testmap 등
server/src/rooms/
  base/PhysicsRoom.ts   고정틱·입력큐·엔티티 레지스트리·상호작용 실행(공통 뼈대)
  baseworld/            BaseworldRoom + schema (향후 lobby·race·mapTest 형제)
client/src/
  netphysics/  predict(자기예측)·interpolate(고스트 보간)·reconcile(자기위치 송신)·
               rideOffset(표면 추종)·squash(연출)
  rooms/baseworld/  Scene + connect
  devconsole/  Console·mount + commands (DEV 빌드에서만 활성)
```
핵심 원리 두 가지:
1. **`shared/physics`는 엔티티가 뭔지 모른다**(순수 엔진). "플레이어"는 `entities/player`로 분리.
   나중에 몬스터·발판을 넣어도 엔진은 안 건드린다.
2. **모든 수치는 `tuning.json` 한 곳**에서 온다(코드에 하드코딩 금지). 개발자 콘솔 `tune`으로
   실시간 조정.

### 9-3. 개발자 콘솔
- 백틱(`) 토글. `join/tp/tune/hitbox/serverview/macro` 등.
- **DEV 빌드에서만 활성**(프로덕션은 코드째 제외). 방장 개념 없음.
- `serverview`: 모든 엔티티의 스프라이트 박스(옵션1)/히트박스(옵션2)/서버 수신 상태(옵션3)를
  태그로 필터해 보는 범용 디버그 뷰어.
- `macro`: 키 입력을 녹화해 반복 재생(혼자서 2인 충돌 테스트용).
